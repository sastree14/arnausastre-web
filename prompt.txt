Necesito mejorar el workflow de LinkedIn Pack para que pueda funcionar en modo automático consultando Google Sheets, además del modo manual actual.

Contexto actual:
Ya existe un workflow llamado:

.github/workflows/generate-linkedin-pack.yml

Actualmente se ejecuta con workflow_dispatch y exige introducir manualmente:

* article_slug
* article_path
* publish_week_start
* language
* dry_run

También existe el sistema:

* scripts/linkedin_pack/generate_pack.py
* prompts/linkedin_pack_prompt.md
* content/linkedin/

Objetivo:
Añadir un modo automático que consulte el Google Sheet editorial, detecte qué artículos ya publicados no tienen LinkedIn Pack generado todavía, seleccione el artículo pendiente más antiguo y genere el pack para ese artículo.

No eliminar el modo manual actual. Mantener ambos modos.

Funcionamiento deseado:

1. El workflow debe aceptar un input nuevo:

mode

con valores:

* manual
* auto

Valor por defecto:
auto

2. Si mode = manual:
   Mantener el comportamiento actual. Usar article_slug / article_path.

3. Si mode = auto:
   El script debe consultar Google Sheets, leer la pestaña Articles Index y detectar artículos publicados que todavía no tengan LinkedIn Pack.

Criterios:

* Considerar solo artículos con Published = TRUE, true, yes, sí o equivalente.
* Leer al menos estas columnas si existen:

  * Title
  * Slug
  * Published
  * Date
  * Industry
  * Role
  * Theme
  * Summary
  * Key metrics

4. Para saber si un artículo ya tiene LinkedIn Pack:

* Revisar los JSON existentes en content/linkedin/
* Leer el campo source_article_slug de cada JSON
* También aceptar fallback por nombre de archivo si hiciera falta
* Si el slug del artículo ya aparece en algún JSON, considerarlo ya cubierto

5. Si hay varios artículos publicados sin LinkedIn Pack:

* Ordenarlos por Date ascendente
* Elegir el más antiguo
* Si Date está vacío o no parsea, ponerlo al final
* Si hay empate, ordenar por Slug

6. Si no hay ningún artículo pendiente:

* El workflow debe terminar correctamente, sin fallar
* Imprimir un mensaje claro:
  “No pending published articles without LinkedIn Pack.”
* No crear commit
* No abrir PR

7. Si encuentra un artículo pendiente:

* Usar su Slug como article_slug
* Usar publish_week_start:

  * si el usuario lo pasa manualmente, usar ese valor
  * si está vacío, calcular el próximo lunes desde la fecha actual del workflow
* Generar el LinkedIn Pack igual que ahora
* Guardarlo en content/linkedin/
* Crear commit en branch linkedin
* Abrir PR como ahora

Google Sheets:
Reutilizar la misma lógica, dependencias, credenciales y variables de entorno que ya usa el content pipeline actual para leer Google Sheets. No duplicar innecesariamente código si ya existe una utilidad reutilizable.
Si no existe una utilidad clara, crear una función pequeña y aislada dentro de scripts/linkedin_pack/ para leer Articles Index.

Variables/secrets:
No hardcodear nada.
Usar los mismos secrets existentes que usa el pipeline editorial para acceder a Google Sheets.
Usar GEMINI_API_KEY igual que ahora.

Validaciones:

* Si mode = auto y no se puede leer Google Sheets, fallar con error claro.
* Si falta la columna Slug en Articles Index, fallar con error claro.
* Si falta Published, fallar con error claro.
* Si falta Date, no fallar; solo ordenar esos artículos al final.
* Si el artículo seleccionado no existe en content/articles/{slug}.mdx, fallar con error claro indicando el slug.

Cambios en GitHub Actions:
Actualizar .github/workflows/generate-linkedin-pack.yml para incluir:

mode:
description: "Generation mode"
required: true
default: "auto"
type: choice
options:
- auto
- manual

article_slug debe dejar de ser obligatorio si mode = auto.
article_path también debe ser opcional.
publish_week_start debe poder quedar vacío en auto para que el sistema calcule el próximo lunes.
language puede mantener default "en".
dry_run se mantiene.

Resultado esperado:
Poder ejecutar el workflow sin introducir article_slug.
El workflow mira Articles Index, encuentra el artículo publicado más antiguo sin LinkedIn Pack y genera automáticamente el JSON.

No publicar en LinkedIn todavía.
No tocar publish_linkedin.py salvo que sea necesario para compatibilidad.
No romper el modo manual.
