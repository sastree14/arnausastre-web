Necesito que implementes una nueva capa de workflow para LinkedIn en este repositorio, conectada al sistema editorial existente.

Contexto:
Actualmente el sistema genera artículos para la web de SC-Analytics desde Google Sheets / Gemini / GitHub Actions. Los artículos se guardan en el repositorio y se revisan mediante una rama editorial antes de hacer merge.

Objetivo:
Crear un sistema paralelo para generar un “LinkedIn Pack” semanal a partir de cada artículo generado. No debe publicar todavía en LinkedIn por API, pero debe dejar toda la estructura preparada para que en el futuro solo haya que añadir secrets y activar el modo API.

Nueva rama:
Crear o usar una rama única llamada:

linkedin

No usar mayúsculas.

Flujo deseado:

1. El artículo se genera normalmente.
2. A partir del artículo final, se llama a Gemini con un prompt específico para generar 5 publicaciones de LinkedIn.
3. Las publicaciones deben corresponder a:

   * Lunes: contexto de la industria y presentación de la semana.
   * Martes: problema principal relacionado con procesos, datos o decisiones.
   * Miércoles: caso práctico simplificado con números.
   * Jueves: hipótesis y razonamiento tipo consultor senior para abordar el problema.
   * Viernes: resumen semanal, aprendizajes principales y enlace al artículo completo.
4. El output debe guardarse en un archivo JSON estructurado dentro de:

content/linkedin/

Ejemplo de nombre:

content/linkedin/2026-06-23-retail-forecasting.json

Estructura esperada del JSON:

{
"campaign_id": "2026-06-23-retail-forecasting",
"source_article_slug": "...",
"source_article_url": "...",
"industry": "...",
"theme": "...",
"language": "en",
"status": "ready_for_review",
"approved": false,
"publish_mode": "manual",
"created_at": "...",
"posts": [
{
"day": "monday",
"publish_date": "2026-06-23",
"post_type": "industry_context",
"title": "...",
"text": "...",
"image_required": false,
"image_prompt": "",
"image_path": "",
"hashtags": ["#DecisionAnalytics", "#Forecasting"],
"published": false,
"published_at": null,
"linkedin_post_url": null
}
]
}

Reglas importantes:

* El sistema debe generar contenido listo para copiar y pegar en LinkedIn.
* No publicar automáticamente todavía.
* Preparar el código para que en el futuro exista un modo API.
* El campo publish_mode debe aceptar al menos:

  * manual
  * api
* Si publish_mode = manual, solo se genera el JSON.
* Si publish_mode = api, en el futuro se deberá publicar usando LinkedIn API.
* No hardcodear tokens ni credenciales.
* Preparar variables de entorno futuras:

  * LINKEDIN_MODE
  * LINKEDIN_ACCESS_TOKEN
  * LINKEDIN_ORGANIZATION_ID
  * LINKEDIN_AUTHOR_URN
  * LINKEDIN_API_VERSION
* Añadir validación para que nunca se publique nada si approved no es true.
* Añadir validación para que nunca se publique dos veces si published ya es true.
* Dejar preparado un script futuro tipo:

scripts/publish_linkedin.py

aunque inicialmente puede quedar en modo dry-run/manual.

Prompt de Gemini:
Crear un prompt específico para transformar el artículo en 5 publicaciones de LinkedIn siguiendo el posicionamiento de SC-Analytics:

SC-Analytics es una consultora de decision analytics especializada en forecasting, optimización, machine learning, modelización matemática, automatización y sistemas de apoyo a la decisión.

Tono:

* Profesional
* Claro
* Técnico pero entendible
* Sobrio
* Orientado a negocio
* Sin humo de IA
* Sin exageraciones
* Con foco en decisiones, trade-offs, restricciones, métricas e impacto real

Cada post debe tener:

* Hook inicial
* Desarrollo
* Insight operativo
* Cierre suave
* Hashtags limitados a 3-5
* No usar emojis salvo que esté explícitamente configurado
* No hacer promesas exageradas
* No inventar datos externos no presentes en el artículo; si usa números para el caso práctico, deben ser simplificados y claramente ilustrativos.

Crear también una plantilla de prompt editable, idealmente en:

prompts/linkedin_pack_prompt.md

Workflow de GitHub Actions:
Crear un nuevo workflow llamado algo como:

.github/workflows/generate-linkedin-pack.yml

Debe poder ejecutarse manualmente con workflow_dispatch.

Inputs deseados:

* article_slug
* article_path
* publish_week_start
* language
* dry_run

El workflow debe:

1. Leer el artículo existente.
2. Generar el LinkedIn Pack con Gemini.
3. Validar el JSON.
4. Guardarlo en content/linkedin/.
5. Crear commit en la rama linkedin.
6. Abrir PR desde linkedin hacia main o dejar preparado el cambio para revisión.

No romper el workflow editorial existente.
No modificar la publicación web actual salvo que sea estrictamente necesario.
Mantener el sistema desacoplado: generación de contenido por un lado, publicación por otro.

Resultado final esperado:
Un sistema donde yo pueda ejecutar un workflow, revisar el JSON generado, hacer merge y tener las publicaciones de LinkedIn listas para publicar manualmente. En el futuro, cuando LinkedIn apruebe el acceso de empresa, solo tendremos que activar el modo API y añadir los secrets correspondientes.
