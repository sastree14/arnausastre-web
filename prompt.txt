CONTEXTO DEL PROYECTO

Este repo (arnausastre-web) es la web de SC-Analytics, una consultora de
datos/ML. Next.js 16 (App Router) + React 19 + TypeScript. Los artículos del
blog ("insights") viven como objetos TypeScript tipados en lib/articles.ts:

  export interface Article {
    slug: string
    titleEn: string
    titleEs: string
    date: string
    readingTime: number
    tagsEn: string[]
    tagsEs: string[]
    excerptEn: string
    excerptEs: string
    bodyEn: string
    bodyEs: string
  }

No hay MDX. bodyEn/bodyEs son template strings de texto plano con **negrita**
estilo markdown ligero. NO existe todavía un campo image — hay que añadirlo en
esta tarea como `image: string` (ruta relativa dentro de public/, p.ej.
"/insights/why-x-fails.svg").

Brand kit oficial — paleta fija, no inventar otros colores:
  Fondo:        #0D1B2A
  Azul medio:   #1E3A5F
  Línea azul:   #496C8A
  Blanco roto:  #F5F7FA
Tipografía: serif clásica (Georgia o similar) para títulos, cursiva reservada
para énfasis editorial (igual que el home: "Better business outcomes." en
cursiva). El monograma "SC" ya vive en public/brand/ — no lo regeneres, solo
puedes referenciarlo como marca de agua discreta si encaja.

Tono de marca (extraído de los 4 artículos ya publicados, respétalo en todo
texto que generes): frases cortas y declarativas, sin adjetivos de relleno,
mucha contraposición tipo "la tecnología rara vez es el problema" / "no es
una cuestión de X, es de Y", títulos en formato "Why most X fail in
practice" / "The hidden cost of Y" / "Building Z that companies actually
use". Nunca tono de venta agresivo ni superlativos vacíos ("revolucionario",
"game-changing", etc.).

OBJETIVO DE ESTA TAREA — pipeline completo de UN artículo, de punta a punta

Quiero un workflow ejecutable manualmente (workflow_dispatch) que haga todo
esto, en este orden, parando con un error claro si cualquier paso falla en
vez de continuar a ciegas con datos parciales:

1. LEE "Topics Bank" de la Sheet. Si está vacía, falla con mensaje claro
   ("Topics Bank no tiene filas — añade al menos una idea antes de
   ejecutar este workflow") y termina ahí, sin crear PR ni Issue de error
   confuso.

2. LEE "Content Pipeline" para saber qué filas de Topics Bank ya están
   cubiertas (cruza por Theme+Industry). Construye la lista de temas
   pendientes.

3. Si hay temas pendientes, ELIGE UNO al azar (registra en el log qué
   semilla/criterio se usó, para que sea trazable). Si no hay ninguno
   pendiente, termina con mensaje claro, sin error.

4. INVESTIGA por internet usando Brave Search API: 3-5 queries relevantes
   sobre cómo se aplica análisis de datos / forecasting / optimización / ML
   a esa industria y ese "Decision Problem" concreto de Topics Bank. Guarda
   las URLs fuente.

5. REDACTA el artículo completo, bilingüe (inglés y español), usando la API
   de Anthropic (Claude), con:
   - El tono de marca descrito arriba como contexto fijo del prompt
   - El contenido de Industries (si existe) + lo investigado en el paso 4
     como contexto factual
   - Longitud objetivo similar a los 4 artículos ya existentes (puedes leer
     lib/articles.ts para calibrar longitud real, no asumas un número)
   - Debe producir TODOS los campos de la interfaz Article, en el formato
     TypeScript exacto, listo para insertar en el array

6. GENERA el objeto Article en TypeScript y lo INSERTA en lib/articles.ts,
   añadiendo también el campo `image` apuntando a la ruta que generarás en
   el paso 7. No reescribas el archivo entero a mano — usa una inserción
   quirúrgica que preserve el resto de artículos intactos. Actualiza también
   la interfaz Article para incluir `image: string` si no existe ya.

7. GENERA la imagen de cabecera como SVG estático (no uses ninguna API de
   generación de imagen, esto es composición geométrica programática):
   - Fondo #0D1B2A a pantalla completa
   - Zona izquierda (~42% del ancho) vacía, sin elementos gráficos — se
     reserva para que el HTML real del título se monte encima
   - Zona derecha: un motivo de líneas finas y nodos en #496C8A con puntos
     de énfasis en #F5F7FA, generado con una semilla determinista derivada
     del slug (mismo slug → misma composición siempre, usa por ejemplo
     sha256 del slug como semilla de un RNG simple, no uses random() puro)
   - Guárdalo en public/insights/{slug}.svg

8. RENDERIZA esa imagen en app/insights/[slug]/page.tsx replicando el patrón
   compositivo del home (texto a la izquierda, visual a la derecha) — mira
   cómo está hecho app/page.tsx para mantener consistencia, no inventes un
   layout nuevo desde cero.

9. ESCRIBE una fila nueva en "Content Pipeline" con el mapeo de campos
   especificado arriba.

10. ABRE un Pull Request (no hagas commit directo a main) con todos los
    cambios: lib/articles.ts actualizado, la imagen SVG nueva, y el page.tsx
    si lo tocaste. Título del PR: "New article: [titleEn]". Cuerpo del PR
    debe incluir: el excerpt en ambos idiomas, las fuentes investigadas, y
    un recordatorio de que hay que revisar el contenido antes de hacer merge.
