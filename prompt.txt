CONTEXTO DEL PROYECTO

Este repo (arnausastre-web) es la web de SC-Analytics, una consultora de
datos/ML. Está construido en Next.js 16 (App Router) + React 19 + TypeScript.
Los artículos del blog ("insights") viven como objetos TypeScript tipados en
lib/articles.ts (interfaz Article: slug, titleEn, titleEs, date, readingTime,
tagsEn, tagsEs, excerptEn, excerptEs, bodyEn, bodyEs). No hay MDX. El cuerpo es
texto plano con **negrita** estilo markdown ligero. NO existe todavía un campo
de imagen en la interfaz — lo añadiremos en esta tarea.

Brand kit oficial (no inventar otros colores):
  Fondo:        #0D1B2A
  Azul medio:   #1E3A5F
  Línea azul:   #496C8A
  Blanco roto:  #F5F7FA
Tipografía: serif clásica (Georgia o similar) para títulos, con la cursiva
reservada para énfasis editorial (igual que el home: "Better business
outcomes." en cursiva). El monograma "SC" ya vive en public/brand/.

OBJETIVO DE ESTA TAREA

Quiero un primer workflow MANUAL (workflow_dispatch, no cron todavía) que se
pueda ejecutar a mano desde la pestaña Actions de GitHub, y que haga lo
siguiente, paso a paso, deteniéndose si algo falla en vez de continuar a
ciegas:

1. Lea mi Google Sheet "SC-Analytics — Editorial System" (pestañas: Content
   Pipeline, Topics Bank, Industries, Prompts, Published Content, Content
   Strategy) usando la API de Google Sheets con una Service Account.

2. Determine qué temas/industrias de la pestaña "Topics Bank" todavía NO
   tienen una entrada correspondiente en "Content Pipeline" (es decir, no se
   ha escrito artículo sobre ellos todavía). Si "Topics Bank" está vacía o
   todo ya está cubierto, el workflow debe terminar con un mensaje claro en
   los logs ("no hay temas pendientes") y no fallar de forma confusa.

3. De entre los temas pendientes, elija UNO al azar (random, pero registra la
   semilla/elección en el log para que sea trazable).

4. Investigue por internet cómo se aplica el análisis de datos / forecasting /
   optimización / ML a esa industria concreta, usando la Brave Search API
   (api key vía secret de GitHub llamado BRAVE_API_KEY). Necesito 3-5
   resultados relevantes y recientes, no solo el primero que salga.

5. NO escriba el artículo todavía en esta primera versión — el objetivo de
   esta tarea es solo validar los pasos 1-4 funcionando de punta a punta.
   Como resultado final, el workflow debe:
   a) imprimir en el log un resumen claro: tema elegido, industria, ángulo
      sugerido, y un resumen de 3-5 líneas de lo que encontró en la
      investigación web (con las URLs fuente)
   b) escribir ese mismo resumen como un comentario en un Issue de GitHub
      creado automáticamente (título: "Borrador propuesto: [tema] — [fecha]"),
      para que yo pueda revisarlo desde el móvil sin tener que mirar logs de
      Actions
